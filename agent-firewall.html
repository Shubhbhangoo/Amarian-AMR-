03 RELEASE LOG

THE BOUNDARY KEEPS GETTING SMALLER

v2.8
owns the record.

Each release attacks a different failure mode while keeping authorize() as the sole allow origin. The goal is not more features. It is fewer ways for reality to become ambiguous.

v2.8
Side-effect commit protocol

Durable intent, exactly one recorded attempt, explicit SUCCEEDED / FAILED / UNKNOWN outcomes, receipts as observations, and explicit reconciliation. Unknown is never silently promoted to success.

CURRENT
v2.7
Execution authority continuity

An execution lease continues one allow and re-establishes its authority basis before progression. Revocation or expiry mid-flight becomes an explicit terminal failure.

LEASE
v2.6
Concurrency integrity

Widening authority changes are bracketed as intervals. A dirty authorization window is refused rather than reconstructed from inconsistent reads.

TIME
v2.5
Attack release

Hostile input and injected failures were pushed through the shipped authorization boundary until twelve paths that raised instead of deciding became explicit denials.

ATTACK
v2.4
Aegis adaptive authority

Live grants can be narrowed, suspended, revalidated or revoked while work is running, without introducing a second authorization path.
